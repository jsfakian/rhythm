RHYTHM Repository Automated Upload Instructions

Guidance for partners preparing Excel metadata, anonymized CT ZIP files and the JSON manifest for automated upload.

Important: the automated upload tool does not anonymize DICOM files. All CT studysets must be anonymized locally before packaging and upload. The final RHYTHM Repository Study ID is assigned by the server, not by the partner-side tool.

RHYTHM Repository Upload Tool

Provider Instructions for Metadata Manifest and Anonymized CT ZIP Upload

1. Purpose

This tool helps RHYTHM partners prepare a structured upload package for the RHYTHM Repository Upload Platform.

Each provider prepares:

  1. An Excel metadata file with one row per CT studyset.
  2. One ZIP file per anonymized CT studyset.
  3. A JSON manifest generated by the RHYTHM manifest tool.

The JSON manifest is uploaded together with the ZIP files. The repository server validates the upload and assigns the final RHYTHM Repository Study ID.

The partner does not manually create the Repository Study ID.

2. Privacy and anonymization requirements

Before using this tool, all CT studysets must already be anonymized locally by the submitting institution.

The ZIP files and Excel template must not contain:

  • Patient name
  • Original hospital PatientID
  • Accession number
  • Date of birth
  • National identifier
  • Any other direct patient identifier

The tool does not anonymize DICOM files. It only prepares the upload manifest.

3. Files supplied to partners

Partners will receive:

rhythm_server_assigned_metadata_template.xlsx
create_rhythm_server_assigned_manifest_gui_with_uid.py
create_rhythm_server_assigned_manifest_gui_with_uid.exe

The Python script and Windows executable perform the same task. The executable can be used on Windows without running Python commands.

4. Recommended folder structure

Create one working folder, for example:

C:\RHYTHM_Upload\
│
├── metadata\
│   └── rhythm_server_assigned_metadata_template.xlsx
│
├── zips\
│   ├── study_001_anonymized.zip
│   ├── study_002_anonymized.zip
│   └── study_003_anonymized.zip
│
└── output\

The zips folder should contain the anonymized CT studyset ZIP files.

Each ZIP file should contain one CT studyset only.

5. Completing the Excel metadata template

Open:

rhythm_server_assigned_metadata_template.xlsx

Complete one row per ZIP file.

Column Description
filename Exact ZIP filename, for example study_001_anonymized.zip
site_code Coded submitting site, for example S001. Must match (case-insensitively) the submitting site of the protocol referenced by protocol_id below — the server rejects the row otherwise.
protocol_id UUID of a protocol already registered in the RHYTHM app. Copy it from the Protocol Records page — see section 6 below. The server derives the anatomical region, clinical indication, contrast, protocol type, examination group, and scanner from this protocol; none of those are typed here.
patient_weight_kg Patient weight in kg
patient_age_years Patient age in years
ctdivol_mgy CTDIvol in mGy
dlp_mgy_cm DLP in mGy·cm
image_quality Image-quality category, e.g. Acceptable

The value in filename must exactly match the ZIP filename in the selected ZIP folder.

Example:

filename: study_001_anonymized.zip

must match:

C:\RHYTHM_Upload\zips\study_001_anonymized.zip

6. Finding your Protocol ID

Every studyset must reference a protocol already registered in the RHYTHM app — this replaces the older clinical indication / anatomical region / contrast / patient group / scanner columns entirely.

  1. Log in to the RHYTHM app and open the Protocol Records page (/protocols/records/).
  2. Find the row matching the scanner, indication, region, contrast, and age/weight group this studyset was actually acquired under.
  3. Copy the value from its Protocol ID column (a UUID, e.g. 5f6a1e9c-6b1a-4b7e-9c2d-8a1e5f6a1e9c).
  4. Paste it into the protocol_id column for that row in the Excel template.

If the protocol you need isn't listed yet, it must be registered first via the app's Protocol GUI before you can reference it here — the tool cannot create one for you.

7. Preparing ZIP files

Each ZIP file should contain the already anonymized DICOM files for one CT studyset.

Recommended rules:

  1. One ZIP file corresponds to one CT studyset.
  2. The ZIP should contain DICOM files only, where possible.
  3. The ZIP should not contain identifiable reports, screenshots, or hospital exports.
  4. The ZIP filename must match the filename column in the Excel template.
  5. The ZIP should not contain multiple different StudyInstanceUID values.

The tool inspects each ZIP file and extracts the anonymized DICOM StudyInstanceUID.

8. Running the Windows executable version

Use this option if you receive:

create_rhythm_server_assigned_manifest_gui_with_uid.exe

Steps:

  1. Double-click the executable.
  2. Select the completed Excel metadata template.
  3. Select the folder containing the ZIP files.
  4. Select where to save the output JSON manifest.
  5. Optionally enter a batch ID, for example:
S001-2026-07-12-001
  1. Keep Include ZIP SHA-256 checksums in manifest enabled.
  2. Click Generate JSON Manifest.
  3. Wait until the tool reports that the manifest has been created successfully.

The tool creates:

rhythm_upload_manifest.json
rhythm_upload_manifest_index.csv

The JSON file is submitted to the repository together with the ZIP files. The CSV index file is for partner review.

9. Running the Python version

Use this option if you receive:

create_rhythm_server_assigned_manifest_gui_with_uid.py

Install prerequisites:

pip install pydicom openpyxl

Start the graphical interface:

python create_rhythm_server_assigned_manifest_gui_with_uid.py

Optional command-line use:

python create_rhythm_server_assigned_manifest_gui_with_uid.py ^
  --input C:\RHYTHM_Upload\metadata\rhythm_server_assigned_metadata_template.xlsx ^
  --zip-folder C:\RHYTHM_Upload\zips ^
  --out C:\RHYTHM_Upload\output\rhythm_upload_manifest.json ^
  --batch S001-2026-07-12-001

10. What the tool checks

The tool checks that:

  1. The metadata file can be read.
  2. The required metadata columns are present.
  3. protocol_id is a syntactically valid UUID.
  4. Each filename exists in the selected ZIP folder.
  5. Each listed file is a valid ZIP archive.
  6. Each ZIP contains readable DICOM files.
  7. Each ZIP contains one DICOM StudyInstanceUID.
  8. The DICOM StudyInstanceUID can be extracted and included in the JSON manifest.
  9. A ZIP SHA-256 checksum can be calculated, if enabled.

The tool only checks that protocol_id looks like a UUID — it does not confirm the protocol actually exists or belongs to the right site. That confirmation happens server-side, at upload time (see section 12).

If a ZIP contains more than one StudyInstanceUID, the tool stops and reports an error. The ZIP should then be reviewed and split so that each ZIP contains only one CT studyset.

11. What the generated JSON contains

The generated JSON manifest includes:

  • ZIP filename
  • ZIP file size
  • ZIP SHA-256 checksum
  • DICOM StudyInstanceUID
  • DICOM PatientID, if present in the anonymized DICOM headers
  • DICOM SeriesInstanceUID list
  • Number of DICOM series
  • Number of DICOM instances
  • Site code
  • Protocol ID
  • Patient weight
  • Patient age
  • CTDIvol
  • DLP
  • Image-quality category

Example JSON item:

{
  "ref": "ROW0001",
  "filename": "study_001_anonymized.zip",
  "dicom_uid": "2.25.23890534782093478203948203948203948",
  "dicom": {
    "patient_id": "P-8F3KQ9M2X7AD",
    "study_uid": "2.25.23890534782093478203948203948203948",
    "uid_type": "StudyInstanceUID",
    "series_uids": [
      "2.25.90823475098237450982374509823745098"
    ],
    "series_count": 1,
    "instance_count": 180
  },
  "site_code": "S001",
  "protocol_id": "5f6a1e9c-6b1a-4b7e-9c2d-8a1e5f6a1e9c",
  "patient_weight_kg": 28,
  "patient_age_years": 8,
  "ctdivol_mgy": 18.4,
  "dlp_mgy_cm": 320.5,
  "image_quality": "Acceptable"
}

protocol_id must be the UUID of a protocol already registered in the RHYTHM app (see section 6). The server derives anatomical region, clinical indication, contrast, protocol type, examination group, and scanner from it, and verifies site_code matches that protocol's own site (case-insensitively).

12. Uploading to the repository

After generating the manifest, upload the following through the RHYTHM Repository Upload Platform:

  1. rhythm_upload_manifest.json
  2. All ZIP files listed in the manifest

The repository server will:

  1. Read the JSON manifest.
  2. Receive the corresponding ZIP files.
  3. Verify ZIP checksums.
  4. Resolve protocol_id against the RHYTHM app's registered protocols, and reject the item if it doesn't exist or its site doesn't match site_code.
  5. Re-inspect DICOM headers inside the ZIP files.
  6. Confirm that the DICOM StudyInstanceUID inside each ZIP matches the dicom_uid in the manifest.
  7. Check for duplicate uploaded studies.
  8. Assign the final RHYTHM Repository Study ID centrally.
  9. Return a compact response listing the assigned Repository Study IDs.

13. Example server response

{
  "v": "1.0",
  "type": "server_assigned_repo_id_response",
  "site": "S001",
  "batch": "S001-2026-07-12-001",
  "items": [
    {
      "ref": "ROW0001",
      "filename": "study_001_anonymized.zip",
      "repo_id": "RHY-S001-HEADTRAUMA-NC-PH-G4-000126",
      "dicom_uid": "2.25.23890534782093478203948203948203948",
      "status": "ACCEPTED"
    }
  ]
}

The final Repository Study ID is assigned by the server, not by the partner-side tool.

14. Troubleshooting

ZIP file not found

Check that the filename in the Excel template exactly matches the ZIP file in the selected ZIP folder.

File is not a valid ZIP

Re-create the ZIP file using standard ZIP compression and try again.

No readable DICOM files found

Check that the ZIP contains DICOM files and not another nested ZIP file or only screenshots/reports.

Multiple StudyInstanceUID values found

The ZIP likely contains more than one DICOM study. Split the contents into separate ZIP files, one per CT studyset.

Multiple DICOM PatientID values found

This may indicate mixed DICOM datasets or inconsistent anonymization. Review the ZIP contents before upload.

protocol_id does not match a registered protocol

Copy the ID again from the Protocol Records page in the RHYTHM app (section 6) — it must be an exact UUID for a protocol that already exists there.

site_code does not match the submitting site of protocol

The protocol_id you pasted belongs to a different site than the site_code in this row. Use a protocol registered under your own site, or correct site_code.

Excel file cannot be read

If using the Python version, install:

pip install openpyxl

If using the executable version, ensure the Excel file is closed before running the tool.

DICOM UID extraction fails

If using the Python version, install:

pip install pydicom

Also check that the ZIP files contain valid DICOM files.

15. Final checklist before upload

Before submitting to the repository, confirm that:

  • All CT studysets are anonymized.
  • Each ZIP contains one CT studyset only.
  • No ZIP contains direct patient identifiers.
  • The Excel template contains one row per ZIP file.
  • Each filename in the Excel template exactly matches a ZIP filename.
  • Each protocol_id was copied from the correct row on the Protocol Records page, and its site matches site_code.
  • The JSON manifest was generated successfully.
  • The ZIP files and JSON manifest are uploaded together.
  • The partner does not manually assign the Repository Study ID.
